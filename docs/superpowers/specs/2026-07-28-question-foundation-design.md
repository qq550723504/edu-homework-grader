# 统一富题目与来源许可证快照设计

**Issue:** #155（父 Epic #144）
**状态:** 已确认设计
**范围:** 后端数据模型、迁移、内部教师读取契约与回归测试；不实现外部 Provider、检索、组卷或新的前端管理界面。

## 背景与根因

当前 `QuestionVersion` 是稳定的教学与作答边界，但内容只由 `prompt`、可选
`reading_material` 和 `rule_json` 表达。它无法安全表达选项、子题、媒体、解析、外部
来源或内容许可证；若直接覆盖既有字段，会破坏已发布 M1/M2/E1--E4、指纹、测试、批改和
学生作答契约。

本设计采用增量演进：旧字段继续是既有业务的权威兼容投影；新富内容与来源许可证绑定到
不可变 `QuestionVersion`。学生路径只读取本地版本，绝不实时依赖供应商。

## 调研与取舍

- Open edX 的内容库与 XBlock 证明“可复用内容”和“学习交付”应分离；其平台体量与 AGPL
  许可证不适合作为本服务的嵌入式依赖。
- QTIWorks/QTI 的题目和交付分离可作为未来导入/导出互操作参考；本期不在本服务中实现或
  依赖 QTI 运行时。
- 因此本期不引入富文本、QTI、媒体处理或 Provider SDK。先定义有版本的本地 JSON 契约，
  后续适配器在边界处转换。

## 备选方案

1. **推荐：增量内容快照。** 在 `QuestionVersion` 保存版本化 `content_json`，并新增媒体、
   外部来源和许可证快照表。旧字段继续保留并由兼容投影验证。迁移和现有调用面风险最低。
2. **完全规范化题目树。** 立即将题干、选项、子题和答案拆成多张关系表。查询形状清晰，
   但首次迁移、版本不可变性和既有题型兼容风险过高。
3. **只增加外部来源表。** 改动最小，但不能表示富内容或为后续导入建立稳定快照，无法完成
   #155 的基础目标。

选择方案 1。

## 数据模型

### QuestionVersion

新增两个不可空字段：

- `content_schema_version: str`，首个值为 `question-content-v1`；
- `content_json: JSON/JSONB`，只保存可安全持久化的题目展示与教学内容。

`question-content-v1` 的顶层固定为：

```json
{
  "stem": [{"kind": "text", "text": "..."}],
  "reading_material": [{"kind": "text", "text": "..."}],
  "response": {"kind": "legacy-rule"},
  "explanation": [],
  "metadata": {"grade": null, "difficulty": null, "estimated_minutes": null}
}
```

本期只写入 `text` 块与 `legacy-rule` 响应描述；`choice`、`blank`、`subquestion`、`mathml`
和媒体块的枚举保留给后续 schema 小版本扩展。未知块不得进入学生投影。

兼容规则：`stem` 的纯文本拼接必须等于 `prompt`，`reading_material` 的纯文本拼接必须等于
旧字段（空值对应空数组）。创建、编辑和生成审核转换同时写入两套字段；发布、指纹和批改
仍使用既有字段。已发布版本不允许修改两套内容。

### QuestionMediaAsset

每条媒体资产归属一个 `QuestionVersion`，保存：`kind`、受控 `storage_key`、媒体类型、大小、
内容 hash、替代文本、排序与创建时间。数据库不保存二进制数据、公开 URL、签名 URL、令牌或
供应商临时地址。首期只建模型和安全校验，不上传、转码或向学生端投影媒体。

### ExternalContentReference

每条外部引用归属一个 `QuestionVersion`，保存：来源名称、外部标识、来源版本、导入时内容
hash、许可证标识、许可证快照 JSON、允许租户、持久化/学生展示/AI 处理/再分发四项布尔权限、
合同到期时间与创建时间。

许可证快照在创建后不可更新；对外部题目的后续内容或授权变化，只能创建新的 `QuestionVersion`
及新引用。没有持久化和学生展示许可的来源不得创建可发布版本。

## 应用服务与 API

- 新建纯函数模块，负责 `question-content-v1` 验证、旧字段到快照的投影、快照到旧字段的
  一致性校验，以及仅允许的媒体/许可证元数据校验。
- `create_question`、后继草稿、草稿编辑和 AI 候选接受路径使用该模块。旧请求不携带富内容时，
  服务从现有字段生成快照；携带内容时必须与旧字段兼容，否则返回稳定校验错误。
- 既有教师和学生响应保持字段不变。仅增加受教师权限保护的富内容和来源元数据读取字段；
  学生响应不返回许可证细节、外部标识或媒体存储键。
- 外部 Provider、公开 API、检索、媒体上传和前端编辑器明确不在本期。

## 迁移与不可变性

迁移先添加可空列和新表，逐行以 `prompt`、`reading_material` 与 `rule_json` 回填
`question-content-v1`，再将版本和内容列设为不可空。迁移不修改 `prompt`、`rule_json`、指纹、
状态或版本号。

数据库外键以 `QuestionVersion` 为边界；应用层禁止修改已发布版本的富内容、媒体和来源。
后继草稿复制内容快照、媒体和来源记录为新行，保留其来源版本而不复用可变引用。

## 测试与验证

- 模型/迁移：M1、M2、E1--E4 回填后内容与旧字段一致，现有索引和指纹不变。
- 服务：旧 API 创建、编辑、后继草稿和 AI 接受路径均生成一致快照；冲突内容被拒绝。
- 不可变性：已发布版本、许可证快照和外部内容 hash 不能被更新；后继草稿获得独立副本。
- 安全：拒绝 URL、令牌式字段、未经允许的媒体类型和不安全许可证元数据；学生投影没有外部
  ID、许可证 JSON 或存储键。
- 回归：现有 question、assignment、grader、AI 审核与学生浏览器链路继续通过。

## 非目标与后续

本期不实现二一或其他 Provider、教材目录、知识点映射、Paper/Blueprint、智能组卷、DOCX/PDF
导出、开放 API、图搜或富文本编辑器。完成后，Provider 和目录工作只能通过本设计的本地不可变
快照边界进入题目与学生路径。
