# 项目官网首页设计

**日期：** 2026-07-26  
**范围：** `apps/web/app/pages/index.vue` 及其首页样式、渲染测试和站点元数据。  
**目标：** 将现有首页提升为项目官网，同时让学生和教师能直接进入各自工作台。

## 背景与边界

Edu Homework Grader 已具备英语与数学作业的学生作答、反馈订正、教师出题、任务跟进和复核能力。现有首页仅提供简短角色入口，不能完整说明项目价值、工作方式及其可信边界。

本切片只改 Nuxt 首页的内容与展示层。它不新增 API、数据采集、认证流程、账户体系或后台管理功能；也不宣称平台已经完成生产上线或真实学校环境验收。既有 `/student` 与 `/teacher` 路由及其 API 驱动流程保持不变。

## 受众与核心动作

首页同时向三类受众说明价值：

- **学生：** 明确可完成作业、查看反馈和进行订正。
- **教师与学校：** 明确可建题、布置、跟进结果并处理需要专业判断的复核。
- **家长：** 通过可追溯反馈和教师复核理解学习过程的透明度。

首页的首要转换动作不是提交表单或申请试用，而是按角色直接进入现有工作台：学生进入 `/student`，教师进入 `/teacher`。

## 页面结构

### 顶部导航

顶部使用项目名称与站内锚点，帮助访客跳到“平台能力”和“为什么可信”。右侧常驻两个清晰入口：学生入口和教师入口。小屏幕下导航换行或收拢为纵向内容，两个入口仍保持可点击和可辨识。

### 首屏：双工作台入口

首屏以“作业、反馈与教学协作”作为价值主张，并用并列的学生/教师入口卡表达两条真实路径：

- 学生卡：完成今天的作业、查看反馈、进行订正；主按钮链接 `/student`。
- 教师卡：创建与布置任务、查看学习进展、及时复核；主按钮链接 `/teacher`。

两张卡视觉权重相同，避免把学生或教师视为次要受众。窄屏时按学生、教师的顺序垂直排列，按钮占满容器宽度以确保触控可用。

### 面向不同角色的价值说明

在入口下方使用三个简短模块，为学生、教师/学校、家长分别翻译平台价值。该区域不重复入口按钮，而是说明各方能获得的结果，避免官网沦为工作台导航页。

### 平台能力

能力模块用可扫读的卡片或步骤串联完整学习闭环：

1. 英语与数学作业；
2. 规则化自动批改与反馈；
3. 教师查看进展、复核和发布；
4. 学生根据反馈订正，并在需要时申请复核。

文案必须基于已实现能力，使用“支持”“可”等准确表述，不将 AI 候选题、真实 Provider 或生产环境能力描述成默认已上线服务。

### 为什么可信

可信区域明确三项原则：评分规则一致、需要理解语境的结果由教师复核、反馈与处理记录可追溯。其目的不是技术堆砌，而是清楚说明 AI 的辅助边界与教师专业判断的位置。

### 底部

页尾重复学生与教师入口，并提供项目定位文案。当前不加入虚构联系方式、客户徽标、数据指标、下载内容或尚未存在的帮助中心链接。

## 视觉与响应式原则

- 复用现有蓝色、白色与浅灰配色、卡片层级和按钮样式，使首页与教师工作台视觉一致。
- 使用语义化 `header`、`nav`、`main`、`section` 和 `footer`；页面锚点有明确标题，键盘焦点持续可见。
- 采用移动端优先布局：双列内容在约 760px 及以下改为单列；使用 `clamp()` 维持标题和间距的平滑缩放；链接和按钮最小高度保持 44px。
- 不引入图片素材、远程字体或第三方 UI 库，以免增加加载与版权风险；以排版、图形化步骤和现有设计语言建立识别度。

## 实现边界与数据流

首页是静态 Nuxt 页面，仅输出内容与链接。所有角色入口都使用 `NuxtLink`，使浏览器导航沿用既有路由和认证处理。官网不会读取或展示学生、教师、班级、作业或 AI 生成数据，因此没有新的加载、错误或隐私状态。

站点 `title` 与 `description` 更新为能描述平台和受众的中文文案；不加入虚构的 SEO 结构化数据或外部追踪。

## 测试与验收

更新 `apps/web/tests/homepage-rendering.test.ts`，覆盖：

- 页面主标题、学生入口和教师入口；
- 两个入口准确指向 `/student` 和 `/teacher`；
- 面向三类受众的介绍和关键可信原则；
- 不暴露 API 地址、密钥、实现细节或未经证实的生产声明。

执行 Web 单元测试和 Nuxt production build。响应式验收至少检查 320px 宽度下没有横向溢出、角色入口按单列排布、按钮可点击；桌面宽度下两个入口并列并保持可读层级。

## 不在本次范围内

- 登录、注册、申请试用、联系销售或工单系统；
- CMS、博客、案例、下载中心、新闻或多语言切换；
- 修改学生端、教师端、认证、API 或后端能力；
- 生产上线宣称、真实用户指标、学校客户标识或未经验证的合规认证。
